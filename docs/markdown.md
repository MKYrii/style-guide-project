# Правила работы с Markdown

Документация пишется в Markdown и собирается MkDocs. Эти правила проверяются линтером markdownlint (см. `.markdownlint.yml`).

## Базовые правила

- Кодировка файлов — UTF-8, переводы строк — LF.
- Каждый абзац пишется в одну строку, без ручных переносов.
- Блоки (заголовки, списки, таблицы, блоки кода) отделяются пустой строкой.
- Один заголовок первого уровня на файл; уровни не пропускаются.
- Заголовки пишутся символом `#`, без подчёркивания.

## Списки

- Маркированные списки — через дефис `-`.
- Нумерованные списки — `1.`, `2.`, `3.`.
- Вложенность — через три пробела для нумерованных и два пробела для маркированных списков.
- Блоки кода внутри пункта списка выравниваются по тексту пункта.

Пример вложенного нумерованного списка с блоком кода:


1. Установите зависимости:

   ```bash
   pip install -r requirements.txt
   ```

2. Запустите сервер.


## Ссылки

- Ссылки между разделами руководства — относительные: `[Оформление](formatting.md)`.
- Внешние ссылки пишутся целиком вместе с `https://`.
- Текст ссылки описывает цель, а не «здесь».
- Перед публикацией сборка с `mkdocs build --strict` не должна выдавать предупреждений о битых ссылках.

| Плохо | Хорошо |
|---|---|
| `[здесь](https://github.com)` | `[Репозиторий на GitHub](https://github.com)` |
| `[Оформление](https://site.com/formatting.md)` | `[Оформление](formatting.md)` |

## Код

- Встроенный код — в обратных апострофах: `mkdocs.yml`.
- Блоки кода — тремя обратными апострофами с указанием языка: `bash`, `yaml`, `json`, `text`.
- Для вложенных примеров с блоками кода используйте четыре апострофа снаружи.

## Таблицы

- Первая строка — заголовки, вторая — разделитель `|---|---|`.
- Текст в ячейке — одна короткая мысль, без переносов.
- Если таблица шире пяти столбцов, разбейте её на две.

Пример:


| Команда | Назначение |
|---|---|
| `mkdocs serve` | Запустить сервер |
| `mkdocs build` | Собрать сайт |


## Изображения

- Файлы лежат в `docs/assets/`, имя — строчными латинскими буквами через дефис.
- Синтаксис: `![Описание изображения](assets/schema.png)`.
- Alt-текст обязателен (см. [Доступность текста](accessibility.md)).


## Не делать

- Не вставляйте HTML там, где достаточно Markdown.
- Не используйте заголовки для визуального выделения текста.
- Не оставляйте пробелы в конце строк и несколько пустых строк подряд.
