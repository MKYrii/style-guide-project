# Руководство по стилю документации

Это руководство описывает, как писать и оформлять документацию программного проекта: README, руководство пользователя, описание API и внутренние инструкции для разработчиков.

## Для кого

- авторы документации и разработчики, которые пишут тексты;
- рецензенты, проверяющие Pull Request;
- новые участники проекта.

## Как пользоваться

1. Перед написанием документа прочитайте [Общие принципы](principles.md).
2. Выберите шаблон в разделе [Шаблоны документов](structure.md).
3. Пишите по правилам из разделов [Стиль изложения](language.md), [Орфография и пунктуация](spelling.md) и [Оформление текста](formatting.md).
4. Размечайте текст по [правилам работы с Markdown](markdown.md) и учитывайте [точечные рекомендации](tips.md).
5. Сверяйтесь со [словарём и глоссарием](glossary.md) и правилами [доступности текста].
6. Чтобы предложить изменение в само руководство, прочитайте `CONTRIBUTING.md` в корне репозитория.

!!! note "Принцип Docs as Code"
    Документация хранится в Git, проверяется линтерами, проходит ревью через Pull Request и публикуется автоматически.
