# Общие принципы

## Зачем нужны правила

Единые правила делают документацию предсказуемой: читатель быстрее находит нужное, а авторам не нужно спорить о запятых и заголовках при каждом ревью.

## Принципы

| Принцип | Что это значит на практике |
|---|---|
| Читатель прежде всего | Начинайте с задачи читателя, а не с устройства системы |
| Одна мысль — одно предложение | Предложение не длиннее 25 слов |
| Проверяемость | Каждый шаг инструкции можно выполнить и получить описанный результат |
| Единообразие | Один термин — одно значение, одно оформление для однотипных элементов |
| Актуальность | Изменение кода без обновления документации не принимается |
| Минимализм | Если абзац можно удалить без потери смысла, его нужно удалить |

## Что описывает руководство

- стиль изложения: тон, залог, длину предложений;
- орфографию и пунктуацию: «ё», кавычки, даты, иноязычные слова;
- оформление текста: заголовки, списки, выделение, таблицы, изображения;
- правила работы с Markdown;
- шаблоны типовых документов;
- точечные рекомендации для частых ситуаций;
- словарь и глоссарий;
- доступность текста;
- процесс внесения изменений.

## Что руководство не описывает

Правила программирования, оформление кода в репозиториях приложения и дизайн сайта документации. Для них используйте отдельные соглашения проекта.

## Приоритет правил

Если правила конфликтуют, действует такой порядок:

1. Требования законодательства и политики организации.
2. Это руководство.
3. Внешний стиль-гайд, на который ссылается руководство.
4. Мнение автора.
