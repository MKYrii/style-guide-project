# Доступность текста

Правила помогают сделать документацию понятной людям с нарушениями зрения, дислексией, когнитивными особенностями, а также читателям, для которых русский язык неродной, и тем, кто читает с экрана телефона.

## Структура

- Используйте реальные заголовки Markdown, а не крупный полужирный текст: программы экранного доступа строят по ним навигацию.
- Начинайте страницу с краткого резюме в одном-двух предложениях.
- Разбивайте длинные тексты на разделы, ориентируясь на 150-300 слов. Короткую инструкцию не нужно искусственно растягивать.
- Заголовки идут по порядку, без пропуска уровней.

## Язык

- Пишите простыми словами; редкий термин объясняйте при первом использовании.
- Раскрывайте аббревиатуры.
- Избегайте метафор и идиом, которые плохо переводятся.
- Одна инструкция — одно действие.
- Избегайте длинных предложений (ориентир - до 25 слов)

## Ссылки

- Текст ссылки понятен вне контекста: «Скачать руководство (PDF, 2 МБ)».
- Не используйте «здесь», «по ссылке», «подробнее».
- Указывайте формат и размер файла для загрузки.

## Изображения и схемы

- Задавайте альтернативный текст, который описывает смысл, а не внешний вид: `![Схема процесса ревью: автор создаёт PR, рецензент оставляет замечания](review.svg - отзыва)`.
- Для декоративных изображений оставляйте пустой alt-текст.
- Дублируйте содержание схем текстом или списком.
- Не используйте текст в виде картинки.

## Цвет и выделение

- Не передавайте смысл только цветом: добавляйте слово или значок («Ошибка», а не просто красный текст).
- Контрастность текста и фона — не менее 4,5:1.

## Таблицы

- Всегда задавайте строку заголовков.
- Не объединяйте ячейки.
- Не используйте таблицы для вёрстки.

## Видео и аудио

- Добавляйте субтитры и текстовую расшифровку.

## Проверка перед публикацией

- [ ] Заголовки идут по порядку, без пропуска уровней.
- [ ] У каждого изображения есть alt-текст.
- [ ] Ссылки понятны без контекста.
- [ ] Смысл не передан только цветом.
- [ ] Аббревиатуры раскрыты.
- [ ] Основные предложения не длиннее 25 слов.
